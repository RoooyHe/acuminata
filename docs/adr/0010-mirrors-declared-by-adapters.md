# 镜像由适配器声明，来源按站点归并

ADR-0004 指出「靠 `watchlist.label` 字符串相等来分组镜像」是错的：标签是给人看的显示名，改一次文案就会改变哪些域名算同一个站点，进而改变来源归属与去重。决定改为**适配器显式声明镜像**。

一条访问的镜像组 = 适配器 `mirrors` 里包含它的**登记域名**的那一组：

```json
{ "detect": { "pageGlobal": "maccms" },
  "mirrors": [["example.com", "example-mirror.com"]] }
```

`mirrors` 是若干域名组，每组是一个站点的原站与镜像。没被声明过的域名自成一组。组内域名即同一个站点。

## Consequences

- 组的规范键是组里第一个域名（`site`）。`records.site` 在写入时落库，来源聚合（作品行的来源数/站点、详情的来源行、增量合并）一律按 `site`——同一站点的镜像只算一个**来源**（ADR-0004：来源的唯一键是（作品, 站点））。
- `label` 退化为显示名与界面筛选键，不再参与分组。改标签文字不再改变来源归属。
- 老库的 `records.site` 在启动时按当前适配器补一次；改适配器后用 `WorkStore.reparseWorks()` 重算（与身份键同一条重跑通道）。
- 桌面端「打开来源」仍是镜像组内最近访问过的域名，行为不变。
- ADR-0006 的「`domain` / `mirrors` 不再是主轴」指的是**检测**平台时的主轴（改用 `detect` 页面签名）；镜像仍然要在适配器里显式声明，它不会从签名推出来——两个 MacCMS 站签名相同却是两个站点。
