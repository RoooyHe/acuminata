# 本地模式不提供身份判定 / 兴趣归纳 / 候选生成 / 排序，扩展只采集与转送

「分析」在本项目里拆成身份判定 / 兴趣归纳 / 候选生成 / 排序四件事（见 `CONTEXT.md`）。身份判定在写入时做出并落库（ADR-0002），而写入路径、站点适配器（ADR-0003）与 provider 配置都由桌面端拥有。扩展的**本地模式**（`mode=local`）不连桌面端，因而既没有适配器可以把页面缩到最小字段集，也没有地方存放判定结果——留在这里的分析只能把原始字段直接发给模型，正是 ADR-0002 后果条要禁止的做法。

决定：**本地模式不提供这四类分析中的任何一个。** 扩展只做两件事：采集访问、转送访问。ws 模式下的兴趣归纳仍在桌面端触发（`agent:analyze`），其提示词由 `agent/prompts.js` 构建。

## Considered Options

- **本地模式自带分析**（否决）：扩展要自己实现适配器解析、写入时身份判定与 provider 配置，等于把桌面端的写入路径复制一份；而且没有「适配器缩字段」这一步，送出的就是原始字段。
- **扩展把分析请求经 WS 转给桌面端，本地模式禁用**（否决）：ws 模式下桌面端界面已经能触发分析，多一条消息通道只是多一个要核对的出口。
- **扩展完全不具备分析能力**（选中）。

## Consequences

- 扩展的 AI 配置、提示词拼装、provider 与 `AI_ANALYZE` 消息全部删除；`chrome.storage.local` 不再持久化 `ai*` 键。本地模式退化为「只采集、可导出」的隐私模式。
- 模型出口只剩桌面端一处：`main.js` 用 `createAIProviders` 建唯一一个 provider 实例，所有模型提示词都在 `agent/prompts.js` 构建（兴趣归纳 / 自动清理 / 删除反思 / 拒绝推荐）。核对「提示词带了哪些字段」读这一个文件，核对「谁能发出去」读 `main.js`；工具调用另外会把 `agent/tools.js` 声明的字段作为工具结果回给模型。
- 扩展的 `manifest` 把 `connect-src` 中的 `https://*:*` 去掉，只剩本机 WS（`http://localhost:*` 保留给开发期 HMR），网络出口因此也在一行里可核对。
- 本地模式下的历史若要分析，需切回 ws 模式交给桌面端；记录本身不受影响。
