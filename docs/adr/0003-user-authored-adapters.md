# 适配器由用户编写，Acuminata 只定义模板

站点无限多且结构各异，内置适配器永远追不上；让 LLM 自动生成适配器则需要把页面内容送出去，且中文准确率未经标定。决定：Acuminata 只定义适配器的文件格式（模板），具体解析由用户编写，程序运行时加载。兴趣分析只针对用户显式登记的站点，不对全网做。

## Considered Options

- **内置适配器**：O(站点数) 的维护成本。个人项目追不上，而且大部分站点根本没有用户会在意。
- **LLM 生成适配器**：免去用户写正则，但要把页面字段送到云端（与 ADR-0002 的隐私约束冲突），且 Jev 对 CJK 的准确率厂商明确说未经标定。可留作未来的可选辅助，不作为主路径。
- **对全网做兴趣分析**：与 watchlist 的前提直接矛盾——本产品的前提就是用户只在意一小批站点。
- **用户编写适配器**（选中）：适配器可被人工检验（产物是文本），可复用，不依赖任何云端服务。

## Consequences

- 目标用户是愿意写规则的进阶用户，不是普通用户。导入他人编写的适配器等于执行他人的代码，需要一个能力受限的沙箱。
- 适配器解析失败时必须**降级而不是丢弃**。今天 `agent/cluster.js:100` 在正则不匹配时直接 `return { action: "drop" }`——对过滤器这是对的，对解析器这是静默丢失历史。
- 模板目前只覆盖「解析」这一半。解析的输入原料目前只有扩展回传的五个字段（url / title / favIconUrl / description / ogImage），「采集」那一半尚未决定。
