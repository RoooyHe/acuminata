# 作品以内容编号为主键，版本挂在来源上

> **主键部分已被 ADR-0007 取代**：实测不存在跨站通用的单一身份字段。下面保留的是“版本挂在来源上”这个决定，它仍然成立。

同一个内容编号下可能有多个版本（中文字幕、无码、4K）。让版本参与主键会把一部作品裂成多行，计分和推荐都要再去重；直接把版本丢掉，则会永久损失「这个用户只看字幕版」这条偏好信号。决定：`works` 以归一化后的内容编号为主键，版本作为**来源**上的一个属性。

## Considered Options

- **主键 = 编号，丢掉版本**：最简单。但偏好信号永久消失，而且如果不同后缀其实是不同作品（同一编号的另一个剪辑版），将永远无法区分。
- **主键 = 编号 + 版本**：信号最保真，但同一部作品在 `works` 里裂成 N 行，计分需要二次汇总，推荐需要再去重。
- **主键 = 编号，版本在来源上**（选中）：作品不裂，信号不丢。

## Consequences

- 观看次数与每日计分落在 `works` 上：同一部作品无论从哪个站点、哪个版本进入，都累加到同一条。
- `computeDailyScore`（`agent/cluster.js:64`）从 `records` 迁到 `works`——这是「外部补全用户系统」真正生效的那一步。
- **来源**的唯一键是（作品, 站点），与今天「始终使用最近访问的域名做导航」的行为一致。
- `agent_memories` 的键从域名换成作品，兴趣画像才第一次表达「喜欢什么」，而不是「喜欢哪个站」。
- 镜像关系变得显式：适配器里的 `mirrors` 取代今天靠 `watchlist.label` 字符串相等来分组镜像的做法（`agent/cluster.js:27`）。
