# 候选来自站内列表页，由隐藏 BrowserWindow 抓取

站点不提供推荐，也不提供"相关视频"区块，但都提供**列表页**（最新更新、分类、演员、系列），用户就是在那里发现自己想看的东西。决定：适配器用 `list` 声明列表页；App 用隐藏的 `BrowserWindow` 载入这些页面并执行站点的 JS，然后在渲染后的 DOM 上跑与扩展**同一套** `collect` 选择器。

## Considered Options

- **捕获站外发现链路**（用户从搜索引擎/论坛/聚合站进来的路径）：真实使用路径是直接在站内翻列表页，站外链路不存在。不发明需求。
- **HTTP 客户端抓取**：更快更省资源，但站点是 JS 渲染的，而且会拿到和真实浏览器不同的响应；还要另写一套解析。
- **扩展里抓取**：扩展只在你正在看的那一页上，无法访问你没打开的列表页。
- **隐藏 BrowserWindow**（选中）：站点的 JS 正常执行，看起来就是真浏览器；CSS 选择器与扩展完全一致；JS 渲染的列表页也免费支持。

## Consequences

- 一个适配器格式，两个宿主：用户浏览器里的扩展（解析访问）+ App 里的隐藏窗口（抓取候选）。选择器只写一遍。
- 抓取**只在用户点击时触发**，不做后台定时，频次上限由人控制。
- 候选与访问必须分表：候选池是"抓来还没排的"，推荐是"排完序、带理由的"。今天只有后者（`recommendations`），所以它永远是空的。
- 列表页有三个角色，适配器必须能区分：不记录为访问、要被抓取、本身没有作品身份。今天靠 `regexFilter` 丢弃来区分，位置是错的。
- 冒烟测试是真页面：抓取失败必须可见，不能静默。
