# 元数据取自 JSON 搜索接口，不是 DOM 适配器

候选排序需要特征（演员、年份、类别），而视频站的列表条目上只有标题和封面。实测确认元数据站电视猫提供纯 JSON 搜索接口：

```
GET https://www.tvmao.com/servlet/queryobject?type=all&term={关键词}
    Referer: https://www.tvmao.com/

[{"name":"无可替代","year":2026,"actors":"赵今麦 魏大勋","typeId":11,"url":"/kanju/YmFfZmsg"}]
```

它直接给出归一化标题、年份、演员、类别和条目地址。决定：元数据源走 HTTP + JSON 字段映射，**不写 DOM 适配器**——它因此是内置的、零配置的，与逐平台编写的来源适配器是两种东西。`type` 参数无效果（all / drama / movie / 数字 返回一致）。

## Considered Options

- **把元数据站也当普通站点写 DOM 适配器**：可行但没必要。它不是 HTML，没有主题差异，不产生"来源"。
- **不做元数据，只用标题和封面排序候选**：候选无法按内容特征排序，推荐退化成"最新更新的重排"。
- **JSON 接口 + 字段映射**（选中）。

## Consequences

- **搜索是精确/前缀匹配，不是模糊匹配。** 实测：`无可替代` 命中，`无可替代电视剧` 命中 **0**。归一化因此必须产出**多个查询变体**，从最具体到最宽泛依次尝试，第一个命中的胜出——与 `parse.*.from`、`selector`、`attr` 是同一个"有序备选"概念。`《》` 无害，站方自己会剥离。
- **收敛到系列名才会命中，而系列名不是作品身份键。** 实测：`现在就出发第四季（加更版）` 命中 0，`现在就出发` 命中 1，且站方返回的 `name` 就是 `现在就出发`。也就是说剥到系列名能查到，但会把不同季焊在一起——按 ADR-0002，误合是最贵的错误。**系列必须与作品分开记录。**
- **覆盖率不是 100%。** 实测 `太玄·东方阙` 的三个变体全部命中 0，而该作品确实存在。元数据是**可选增强**，不是必经之路；取不到时必须退回廉价信号，不能卡住整条管线。
- 这是对一个第三方接口的依赖。每个用户的机器都会去敲它，必须限流 + 本地缓存，并且把"接口失效"当作已预期的情况处理，而不是异常。
